## 1. 项目定位、平台策略与硬性约束

**Prompt Shelf** 是面向电商视觉创作者的**高质量 AI 生图提示词模板与参考图快速复用工具**，不是自动抓取海量剪贴板历史的产品。用户把值得复现的优秀案例存为模板，结合项目、标签、收藏检索，再在 ChatGPT、豆包等目标输入框中快捷粘贴提示词、效果图或多张参考图。

典型工作流：目标软件输入框处于工作状态 → 按全局快捷键唤出 Prompt Shelf → 检索并选择模板 → 点击提示词 / 单张图片 / 顺序粘贴 → 目标软件按序接收 → 返回工作。管理工作流：打开主素材管理窗口 → 原位创建、编辑、分类与收藏 → 草稿保护、回收站、备份恢复。

**长期平台规划**：首版只对 Windows 做完整发布和验收，随后推出 macOS 版本。**同一套 React 组件、业务模型和 SQLite/资产存储应尽量跨平台共用；系统窗口、前台焦点、剪贴板、模拟输入、托盘和快捷键由平台适配器隔离。** macOS 的真实兼容与权限问题到该平台阶段另行实测，不能仅因 Tauri 支持 macOS 就视为功能自动移植成功。

**硬性红线**：

- **现代化视觉**：严格对齐 V4.11 的简洁商用 UI，不允许以老旧系统控件替换已验收交互。
- **开发/维护成本**：不能为了较小的内存收益造成长期多倍 UI 重写及双端独立维护；WPF 因 Windows 独占而不符合本项目双平台方向。
- **数据所有权**：用户本地 SQLite + 独立原图；原始字节不因列表适配或缓存重建而被裁切、压缩或染色。
- **实际粘贴成功优先**：剪贴板写入成功不代表目标应用粘贴成功；不能以模拟输入日志冒充真实验收。
- **轻量常驻**：按需保留快捷面板，避免主库在后台常驻大量图片解码与无用 DOM；不要用单一“最低内存”数字代替综合体验。
- **Codex 可维护**：源码模块化、测试可复现、依赖固定、无法验证的结论必须明确标注。

### 2.1 快捷调用面板（03_快捷调用面板）

**外观布局**：单列、可调整宽高；每张卡片**效果图在第一位（约 `90×90px`）**；参考图数目不固定，放在其右侧的横向轨道，按原图比例显示并限制过宽/过窄；图片只改变展示尺寸，不修改磁盘原图；不出现永久悬停放大；文本可点击触发整段提示词粘贴。

**专属队列控件，不得丢失**：在 `90×90px` 效果图**右侧**、参考图轨道**左侧**，保留 **`44×90px` “顺序粘贴”按钮**。保留 `.queue .fill` 自下而上宝蓝色水位填充、进行中/已完成状态及 `done/total` 文字，如 `2/4`。该按钮专用于有多张参考图的队列操作，**不等同于单图按钮**；队列状态由 Rust 单一可信来源管理，UI 接收事件更新显示。

**键盘流**（浏览器原型可验证交互，Windows 全局注册仍需实测）：

| 操作 | 固定行为 |
|---|---|
| `Ctrl+Alt+1` | 呼出并切换到“全部”页签 |
| `Ctrl+Alt+2` | 呼出并切换到“最近”页签 |
| `Ctrl+Alt+3` | 呼出并切换到“收藏”页签 |
| 搜索框内 `↑ / ↓` | 移动当前选中案例，必要时滚动到可见区域 |
| 搜索框内 `Enter` | 触发当前选中案例的**完整提示词**粘贴 |
| `Ctrl+K` | 聚焦并全选搜索框内容 |
| `Esc`：有活动队列 | **第一优先级中止后续队列**：已发送/已粘贴项不回滚，未开始项不再发送；队列状态反馈应准确 |
| `Esc`：无活动队列 | 隐藏快捷面板，不退出托盘常驻程序 |

**搜索**：标题+正文采用多词 AND；项目与标签可检索；标题权重大于正文/标签/项目；小型可维护同义词词典、匹配高亮、结果数限制、最近使用与收藏。正常卡片点击提示词或图片应回传目标应用；不能只在模拟输入区增加日志。

**原型核对说明**：03 实际 CSS 含 `.queue{width:44px;height:90px}`、`.queue .fill{bottom:0}`；JS `queueUI()` 以 `done/total` 设置水位，`cancel()` 先结束活动队列；`keydown` 已实现以上快捷键组合。**这是产品交互依据，不是系统级粘贴实现证据。**

### 2.2 主素材管理 UI（01_V4.11 + 02_V5.0）

- **顶栏最终按钮次序**：`新建案例 → 回收站（实时数量角标）→ 搜索词典 → 备份与恢复 ｜ 最小化 / 最大化（还原） / 关闭`。竖向分隔线将功能操作与系统窗口按钮分组；**02_V5.0 新增“备份与恢复”入口优先于 01 的旧顶栏**。
- 资料库标题右侧为两组分段控件：`常规 / 瀑布流`，`最近使用 / 按名称 / 最新创建`；搜索框独占一行；快捷标签行右侧为“清除筛选”，清除筛选不重置布局/排序偏好。
- 左栏常用集合仅“全部 / 收藏 / 最近”；“项目归档 / 标签”打开**向右推开内容区**的二级侧栏。二级栏可排序、单/双列切换，快捷标签 ID/数量/顺序与主库顶部同源一致。
- 常规卡片同排等高、瀑布流自适应；图片轨道可横向翻页；卡片**原位新建/编辑**，编辑时高度自适应；新建中的草稿暂时置于列表顶部，保存后服从当前排序规则。
- 图片支持 Ctrl+V 导入、点击目标图片后精准替换、拖动排序；效果图与参考图角色分开；原图不因 UI 适配发生裁切、压缩、偏色或覆盖。
- 标签/项目拥有稳定关系；重命名保持关联，删除标签/项目不删除案例；失去所属项目的案例成为“独立案例”。
- **Windows 标题栏按钮**在顶栏右侧，按产品定义与窗口生命周期协调；**macOS 不渲染这组三按钮**，预留左侧原生交通灯控件的安全布局空间（见 §4.4）。

### 2.3 数据保存、草稿、回收站与恢复（02_V5.0）

**3.5.1 保存与草稿**：案例的标题、提示词、图片及关系修改使用“显式保存 / 取消”；收藏、已确认排序等简单操作即时保存。卡片原位编辑时，底部显示**琥珀色圆点**及文案 **“未正式保存 · 自动保护草稿”**。切换筛选视图、尝试取消或离开未保存编辑时，出现保存/继续编辑/放弃等明确拦截，不得静默丢数据。意外退出再次启动时弹出 **“发现未完成的案例草稿”**摘要（标题、部分提示词、图片数量、暂存时间）。点击“恢复并继续编辑”后，**只定位原案例并回到卡片原位编辑状态**；草稿暂存不覆盖上一次正式保存的业务记录。新增案例草稿要与已保存案例区别处理。

**3.5.2 回收站**：首次删除进入回收站，弹出 **4.5 秒可点击“撤销”的 Toast**；回收站卡片保留标题、原项目、效果图和参考图、提示词 **2–3 行摘要**、恢复/永久删除按钮；不要增加“已删除”重复徽标。卡片左下方按业务实体实时计算共享引用状态，例如 **“其中 X 张图片仍被其他案例使用”**。永久删除必须二次确认，并且**只清理没有被正常案例、回收站案例、未完成草稿或其他有效关联引用的原图**；复用原图禁止误删。回收站案例所属项目若已删除，恢复时自动变为“独立案例”，案例本体和图片关系保留。删除后的物理回收须处理文件/数据库一致性，不能只凭 UI 引用数字直接 unlink。

**3.5.3 完整备份恢复**：保留 V5.0 的**2×2 数量预检确认弹窗**，展示**正常案例、回收站案例、标签、项目**四类数量，并在正式版按“**当前资料库 vs 待恢复备份**”进行逐类对比，同时显示备份日期、文件名、整体恢复而非合并的影响。正式格式改为**ZIP 包**，包含元数据（例如 `manifest.json`/`data.json` 或经一致性快照导出的 SQLite 数据）、独立原始图片和 SHA-256 校验清单；图片仅存一次。恢复按**检查版本/完整性 → 临时解包 → 核验引用与文件 → 用户确认 → 原子化切换**执行；失败不覆盖现有库。ZIP 大包应支持流式读写及 ZIP64（必要时），不得将所有原图转 Base64 塞入一个 JSON。

**来源链接**：允许输入 `google.com`、`www.apple.com`、`百度.com` 或完整 URL；保存/失焦时按规则补 `https://`，只允许 `http:`/`https:`，禁止脚本等危险协议；用户不需要手动键入协议。

**原型核对说明**：02 确实具有草稿状态文案、草稿摘要恢复、拦截窗、`4500` 毫秒撤销、回收站共享提示和 2×2 恢复统计；但永久删除只是计算模拟，未在电脑磁盘执行；恢复弹窗的 `JSON` 文件读取和旧 URL 解析**不是生产方案**。

## 3. 4.1 数据方案与正式存储约束

**已批准**：SQLite 存文本元数据与关联，本地 `assets/` 存完整原图。与前端 UI、系统粘贴逻辑解耦。

建议逻辑目录（最终位置由 Tauri 应用数据目录 API 与用户数据位置设置确定）：

```text
PromptShelfData/
├── library.db               # 案例、提示词、收藏、标签、项目、图片引用、草稿索引、回收站等
├── assets/                  # 以原始字节 SHA-256 为内容身份；保留原格式和原图字节
│   ├── <sha256>.png
│   ├── <sha256>.jpg
│   └── <sha256>.webp
├── cache/
│   └── thumbs/              # 可重建的预览缩略图，不等于原图
├── drafts/                  # 临时草稿必要的安全暂存内容
└── logs/                    # 诊断日志，不写入图片/提示词敏感全文
```

**职责原则**：案例 `case_id`、跨库稳定 ID 与图片 `asset_id` / 内容 SHA-256 分离；多个案例通过引用表指向同一张物理图片。效果图/参考图角色及排序存关系表。缩略图不参与原始数据身份识别。图片写入先到临时文件，完成校验后再标记为可用；永久删除要计算所有有效引用，必要时延后垃圾回收。SQLite 使用外键约束、迁移版本和索引；一致性备份使用官方在线备份 / 快照机制，不得在 WAL 写入期间直接生拷贝打开的数据库假装成功。

**缩略图缓存新增正式要求**：`cache/thumbs/` 与 `assets/` 分层，按图片 SHA-256、缩略图尺寸/算法版本识别缓存。快捷面板参考图轨道约 90px 高，按 2x DPI 可准备约 180px 高预览；列表仅解码视口内图片，页面卸载/滚动离开后释放不再使用的缓存资源。缩略图可进行仅用于展示的尺寸缩减、缓存压缩；**严禁覆盖原图文件**。质量/透明度需要验收。

**前端图片访问**：使用 Tauri `convertFileSrc` 或等价安全封装生成受控 `asset://`（Windows 下可能呈现 `http://asset.localhost/...`）资源 URL；以 `<img src>` 按需加载缩略图，主图查看时才加载原图。按 Tauri `assetProtocol.scope` 和 CSP **最小授权**，只暴露必要数据目录；绝不把任意本机路径开放给 WebView。**禁止经 IPC 或 SQLite 搬运大图 Base64**；IPC 仅传 ID、路径授权结果、事件、进度和小体积元数据。

**V5.0 的两项必须纠正的旧实现**：

| 项目 | 浏览器 Demo 现状 | 正式技术要求 |
|---|---|---|
| 数据备份 | 自包含 JSON，图片可通过 Base64 数据 URL 内联；导入设有演示体积上限 | ZIP：结构化数据 / 一致性数据库快照 + 独立原图 + 校验；完整预检再恢复 |
| 来源链接 | 直接 `new URL(value)`，无协议域名可能失败 | 接受纯域名，规范化补齐 HTTPS，严格限制安全协议 |

## 4. 技术路线决议与 Tauri 2 架构

### 4.1 三方案最终裁决（方案 A 唯一主线）

| 方案 | UI 现代化 | Windows | macOS 长期支持 | 现有 HTML/CSS 复用 | 结论 |
|---|---|---|---|---|---|
| **A · Tauri 2 + Rust + React/TS** | 能还原 V4.11 | ✓ | ✓，需独立实测平台功能 | **高** | **唯一主线，实施 Windows PoC** |
| B · C# + WPF | 能达现代 UI，但需重写 | ✓ | **无原生跨平台支持**，Mac 需另一套 UI | 极低 | **淘汰，不实施 PoC** |
| C · Rust + GPUI / GPUI CE | 有现代 UI 潜力 | ✓ | 框架/平台成熟度待验证 | 极低 | **暂停研究，不实施 PoC** |

WPF 淘汰原因是**跨平台战略与 UI 重写成本**，不是“视觉老旧”或无法做漂亮界面。GPUI 保留研究资料但不进入本轮实施。若 A 未通过准入，必须提交实测证据并由产品负责人另开技术决策，不能擅自复活 B 或切 C。

### 4.2 双窗口差异化生命周期（Tauri / WebView2 资源风险控制）

**窗口 1：轻量快捷面板** `quick_panel`：与托盘服务配合启动，轻量 DOM / React 页面，仅预装搜索索引必要信息和可见缩略图。平时**隐藏而不是销毁**，保留热态使全局快捷键呼出尽量快速；Rust 主进程负责快捷键监听与状态。面板不能加载完整 V4.11 图库和无限图片解码缓存。

**窗口 2：素材管理** `library_manager`：按需创建，加载完整 V4.11 UI。点击顶栏“关闭”按钮时，先走未保存编辑 / 草稿保护拦截，再按照验证后确定的策略**销毁该窗口/WebView**，回到托盘与隐藏快捷面板；下次打开按需重建。若保留窗口隐藏的缓存策略更省时，应测试后权衡其后台资源成本，不预先把“挂起”写成保证释放。

**关键技术事实**：Tauri `close()` / `destroy()` 可以结束具体窗口或 WebView 的生命周期，但 WebView2 多进程运行时可能与其他窗口共享进程。**不能保证关闭主管理窗口就立即、完全销毁某个独立 WebView2 进程**。必须实测关闭前后全部相关进程工作集 / 私有字节、GPU、CPU、重新打开耗时与编辑状态。隐藏与销毁不可混为一谈。菜单栏关闭按钮和托盘退出必须是不同意图；系统主动退出需安全保存/询问草稿。

建议状态：`QuickPanel = HiddenHot / Visible / QueueActive`；`Library = Absent / Creating / Visible / Closing / Destroyed`；禁止界面状态错乱、重复创建窗口和窗口关闭时意外结束托盘服务。

### 4.3 精准焦点恢复、多格式剪贴板、异步粘贴队列

**Windows 目标捕获**：收到全局快捷键时，在显示/激活快捷面板**之前**由 Rust 记录当前前台窗口 `HWND`、进程标识、时间戳；若同一会话中用户在面板搜索框输入文字，不应把面板自身误记为粘贴目标。粘贴时先验证 HWND 仍有效、目标进程/窗口未意外切换；必要时隐藏面板并尝试恢复前台，再确认当前前台确为原目标后发送键盘输入。**Win32 `SetForegroundWindow` 有系统前台权限限制**：恢复可能被系统拒绝；遇到拒绝应停止发送，显示可操作的失败提示或提供手动复制，而不是盲发 Ctrl+V 到其他窗口。前台窗口恢复与光标/内部网页编辑焦点恢复是两个不同层次，网页输入焦点需对目标软件实机验证。

**图片粘贴事务**：从 `assets/` 读取原始图片字节，并在一次 Windows 剪贴板打开/提交周期中尽可能提供多种兼容表示：注册的 `PNG` 剪贴板格式（完整 PNG 数据与 alpha）、标准 `CF_DIB` 位图兜底，必要时加入 `CF_DIBV5` 以处理透明度和颜色信息；`CF_HDROP` 文件列表应指向**实际存在、在目标完成读取前不会被清理的原图文件路径**。三类格式必须在系统允许和目标程序接受的条件下共存；应测试格式优先级及应用选择哪种表示。**不能仅凭同时写了 PNG/DIB/HDROP 就宣称任何网站都能收到原图、零压缩、无偏色**；浏览器或应用可能主动重新编码/压缩。源图片磁盘文件永不覆盖；传输转换仅为兼容输出。

**内容测试**：至少 PNG 透明背景、JPG 实拍图、WebP、非 1:1 长宽比、含 ICC/色彩差异案例、中文路径文件名。分别核对目标应用附件数、顺序、分辨率、可视透明度及文件大小/像素差异（可获得时）；明确记录是系统粘贴导致，还是目标站点二次处理。

**异步顺序状态机**（位于 Rust，前端只显示状态）：`Idle → Preparing → RestoringFocus → WritingClipboard → DispatchingPaste → Settling / Waiting → Next → Completed`，并有 `Cancelling / Cancelled / Failed`。每一张图片独立写入剪贴板与触发一次粘贴，步进延迟可配置用于真实目标调优；队列同一时刻只运行一份，不能并发争用全局剪贴板。事件推送 `queue_id、case_id、done、total、state、current_asset、error`；`.fill` 自下而上、`done/total` UI 不变。**Esc 在队列执行中先取消**，不会回滚已发送项；不允许把“模拟按键已发送”标注为“目标站点上传成功”。网页缺乏通用的上传成功回执时，计数说明必须明确“已触发/已发送”，真实接收由人工/辅助自动化观察验证。

**窗口/队列生命周期**：目标窗口关闭或失效、用户取消、快捷面板被退出、目标应用切换、目标被前台锁定时，应明确中止/暂停及错误反馈；取消后释放临时状态，**但不要抢先删除 CF_HDROP 仍可能引用的图片路径**。不进行未经许可的目标网站 DOM 注入或提权绕过系统焦点保护。

### 4.4 Windows / macOS 双平台解耦预埋

**Rust 平台 Trait**：将“捕获前台上下文、验证目标、恢复焦点、写剪贴板复合格式、模拟系统粘贴、获取粘贴修饰键”封装为独立接口；业务层只持有平台无关目标令牌和操作结果，不直接操作 Win32。示意（接口名称仅供实现时调整）：

```rust
trait PastePlatform {
    type Target;
    fn capture_target(&self) -> Result<Self::Target, PasteError>;
    fn restore_and_verify_target(&self, target: &Self::Target) -> Result<(), PasteError>;
    fn write_text(&self, text: &str) -> Result<(), PasteError>;
    fn write_image_variants(&self, original: &std::path::Path) -> Result<(), PasteError>;
    fn dispatch_paste_shortcut(&self) -> Result<(), PasteError>;
}

#[cfg(target_os = "windows")]
mod windows;
#[cfg(target_os = "macos")]
mod macos; // 预留接口/编译边界，不冒充已实现
```

如异步队列需要 `async`，由统一服务层适配异步执行，不要求具体 Trait 必须立即采用上述同步签名。Windows 中句柄等原生类型保持在 `windows` 实现内部，业务代码不能散落 `HWND` / Win32 API；macOS 将来根据实际接口使用 `NSPasteboard`、窗口激活、系统事件等实现，并另行处理辅助功能/输入监控等系统许可要求。**macOS 在当前阶段不做功能通过声明。**

**UI / 窗口控制**：共享 React 页面与 design tokens；平台条件化 TitleBar 组件。Windows 顶栏右侧显示最小化/最大化/关闭；macOS 隐藏自定义右侧三按钮并预留左侧系统红黄绿交通灯位置，实际 Titlebar 与拖动区域兼容性必须 Mac 实机验证。事件绑定不应散落在卡片组件中。

**跨平台路径/快捷键**：所有目录拼接必须使用 Rust `Path` / `PathBuf` 或 Tauri 路径 API，禁用硬编码 `C:\\` 和手拼 `\\`；数据库只保留相对素材路径，不保存机器特定绝对路径。键盘 UI 提示使用 `PlatformShortcuts` 映射 Windows `Ctrl` 与 macOS `⌘`（不同动作的具体热键可能需要另定），测试 Windows 全局快捷键冲突与后期 Mac 系统保留快捷键，不能直接硬编码同一组修饰键。

**Tauri 渲染差异**：Windows 使用 WebView2（Chromium），macOS 使用 WKWebView（WebKit）。React/CSS 可以共享，但字体度量、输入法、滚动/文件协议与特定 CSS 特性需要以后跨端回归；不可宣称“一套 Web UI 无需调试即可完全相同”。

### 4.5 UI 与业务分层（准入后进入 4.4）

**React 组件建议层次**：`QuickPanel`、`LibraryManager`、`CaseCard`、`ImageRail`、`QueueButton`、`TagPanel`、`ProjectPanel`、`TitleBar`、`DraftRecoveryDialog`、`TrashCaseCard`、`BackupRestoreDialog`。共用数据模型，区分仅快捷面板加载的轻量投影与主库详细数据，不让 React 组件持有大图 Base64 或 Win32 细节。

**Rust 服务建议**：`case_service` / `search_service` / `asset_store` / `thumb_service` / `clipboard_service` / `paste_queue` / `platform` / `backup_service`。PoC 阶段只实现粘贴与资源验证所需的最小闭环；完整 SQLite CRUD、回收站和备份放在 4.4 正式实现，避免本轮膨胀。

### 6.3 统一验证流程与证据

1. **视觉预检**：把 QuickPanel 的真实卡片和 V4.11/03 的原始样式进行比对，禁止明显老化或草率替换；管理窗口代表性状态按需对照。
2. **资源基线**：新启动、热态隐藏、快捷面板显示、主库显示、主库销毁后、退出进程六类状态分别记录**整个应用相关进程树**的内存（工作集/私有字节）、CPU 与 GPU（条件允许）；不只看主 Rust 进程。空闲 CPU 应接近系统噪声水平，记录异常持续占用。
3. **快捷响应**：从热键事件到面板可交互，分别记录热唤醒和冷建窗口；目标为尽量达到毫秒级（非秒级等待）。**不要先宣布绝对成功阈值；应在 PoC 前固定实机可接受阈值并请用户批准**，实际报告给 P50/P95。
4. **焦点与目标身份**：从浏览器输入框激活、唤出面板、在搜索框输入、选择案例并粘贴；穿插切换应用/关闭目标/锁屏或 UAC 等边界。目标不再有效时应阻止误贴到陌生窗口。
5. **剪贴板格式**：依次测试文本、单张 PNG/JPG/WebP、透明度与非方图；检查目标接收，区分已写剪贴板/已发送 Ctrl+V/目标确实接收三层状态。
6. **多图队列**：4–6 张连续粘贴，设置不同步进延迟，检查无漏、无重复、顺序正确；第 2 张之后按 Esc，验证仅后续停止；变更目标窗口时检查安全停止。
7. **主库资源释放**：打开代表性主库浏览大量卡片后点击关闭，观察真正的进程/内存变化及下次重建耗时。若“仅隐藏”与“销毁”均可用，比较实际数值，再确定生产策略。
8. **跨平台预埋静态检查**：Rust 业务层不得直接引用 HWND/Win32，路径不含固定盘符，前端有平台化标题栏和快捷键配置；macOS 暂不宣称实机通过。

### 6.4 准入、停线、成本与进入 4.4 的决策

**通过的必要条件（全部满足）**：

- **视觉**：PoC 必需界面达到 V4.11 / 03 的现代化视觉水准，不能把原位编辑/图片轨道的正式需求降级；由用户确认。
- **功能**：在列明的目标软件中真实完成文本、单图、顺序多图粘贴；Esc 在队列中优先取消；不误发至错误窗口；已知目标站点限制要明示。可接受的失败处理方式需经用户验收，不得把“复制成功”偷换成“粘贴成功”。
- **资源**：100/500 数据下，热态后台 CPU、进程树内存、面板响应、列表交互、主库释放全部有可重复的实测证据，并满足**测试开始前产品方确认的阈值**；具体阈值在未取得目标硬件数据前不能虚构。
- **工程**：功能在锁定版本的依赖下可重建、主要逻辑有自动化测试，代码模块化，Windows 集成没有不可维护的私有内核补丁；macOS 适配边界清晰。

**触发停线**：出现无法在真实目标恢复焦点、持续吞图乱序、误贴敏感目标、无法释放主管理窗口造成不可接受的空闲资源开销，或修复方案将显著增加维护成本时，**暂停扩大范围**，记录根因和可行降级备选（仅作为讨论，不自动实施）。任何重大功能降级或框架改动必须重新获得用户批准。

**通过后直接进入 4.4**：提交 PoC 源码、编译可执行程序、原始实测、失败项列表与用户验收结论，正式以 Tauri 2 路线开展 React 组件化和 Rust 数据服务开发。**不再补跑 WPF/GPUI，也不再开展 A/B 横向竞赛。**

## 8. 未决项与待验证的技术事实

- **主库关闭策略**：优先尝试销毁管理窗口并只保留热态面板；释放 WebView2 进程/内存幅度需实测，无法保证每关一个窗口必关闭对应进程。
- **前台恢复限制**：`SetForegroundWindow` 受 Windows 规则限制。窗口成功前台化也不能无条件保证网页编辑器内部光标位置恢复；需要目标应用实测。
- **图片格式**：`PNG` 自定义格式、`CF_DIB`、建议的 `CF_DIBV5`、`CF_HDROP` 组合是兼容性策略，不是所有 Web 应用无损接收的保证；不得静默损失 alpha 或错序。
- **队列确认**：所有网站没有统一可靠的“附件上传完成”回执。Rust 的 `done/total` 可计“已触发粘贴”而不能谎称“上传成功”；用户体验文案随测试确定。
- **性能阈值**：由 PoC 前的目标硬件与用户体验基线设定，文档不编造已经测得的速度或内存数据。
- **macOS**：WKWebView CSS 差异、系统快捷键、前台/辅助功能权限、图片粘贴格式、交通灯标题栏均待后续 Mac 实机；当前只要求隔离接口，不实现或宣称通过。
- **生产数据库**：SQLite 表结构、索引、事务、图片垃圾回收与 ZIP64 的最终细节由 4.4 明确定稿，不在 4.2 中无必要地实现全套生产逻辑。
