## 实现说明

- 复用 schema 2 的 deleted_at、deleted_project_name 和 gc_state，不新增持久引用计数或数据库迁移。
- 固定锁顺序为编辑会话 → 资源生命周期 → SQLite；导入从准备到登记与清理互斥。本运行导入资产保守留到退出，覆盖挂入草稿前的空档。
- 输出快照在相同协调入口登记运行期保护，取消队列不立即释放原图保护。物理清理仅启动时进行，重新检查正常案例、回收站、草稿和剪贴板引用。
- 剪贴板检查失败时保留；文件删除失败保留候选重试。恢复已缺文件的候选行时，不把失效路径作为成功导入复用。

2. **回收站界面**：标题、原项目、参考图数量、缩略图和剩余数量、正文摘要正确；搜索仅检索已删案例。恢复/永久删除后计数、空态及两窗同步。
3. **项目与恢复**：删除案例后重命名原项目，恢复关联到当前项目；删除原项目后恢复为独立案例，图片与正文保留。
4. **共享图片**：A、B 共用一张原图，A 内再重复引用该图；共享提示按独立图片/其他案例计算。B 在正常库或回收站时，永久删除 A 都不能损坏 B。
5. **草稿安全**：存在未保存编辑或待恢复草稿时删除/永久删除，检查保护提示和取消路径。只由其他草稿引用的图片仍可恢复；正式内容不被误写。
6. **永久删除确认**：取消确认不改变数据；确认后案例不可恢复。清理延后，不因原图文件暂留误判删除失败。
7. **活动调用保护（免人工测试）**：按用户确认，该场景不作为人工验收要求。保留现有队列模拟、引用保护和 GC 定向测试证据；本项及其中剪贴板重启边界未记为实机通过。
8. **已有功能**：新建、编辑、图片替换与拖动、手动保存、草稿恢复、分类/收藏/最近、全局快捷键、持续粘贴及 Esc 做相关路径回归，保持已验收界面。
